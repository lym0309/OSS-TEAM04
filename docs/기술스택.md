# 기술 스택

> 근거: 수업 자료 「팀 프로젝트 주제 제안」(신동화 교수) + 팀 결정 (2026-11-12)
> 관련 문서: [프로젝트_기획.md](./프로젝트_기획.md)

## 1. 수업에서 정한 기술 조건 (지켜야 함)
| 구분 | 조건 |
|---|---|
| 프론트엔드 | HTML/CSS/JS. 팀원 모두 다룰 수 있으면 **Vite로 만드는 프레임워크** 사용 가능 |
| 백엔드 | **Express** |
| 금지 | Next.js처럼 **서버가 포함된 프레임워크** |
| 규모 | **메모리 512MB 정도**로 돌아가야 함 |
| 데이터 | 공개해도 되는 데이터만 사용 |
| 제한 | 회원가입·로그인·결제와 실제 개인정보 사용 금지, 공식 API가 없는 사이트 크롤링 금지, **유료 API가 있어야만 동작하는 기능 금지** |
| 필수 구성 | 입력하고 결과를 보는 화면, 화면 없이도 확인할 수 있는 계산 규칙, 서버, 서버가 LLM API를 호출하는 곳 1개 이상, 세 사람이 나눌 수 있는 기능 |

## 2. 확정된 스택
| 레이어 | 기술 | 비고 |
|---|---|---|
| 프론트엔드 | **React + Vite** → **Vercel** 배포 | 정적 SPA로만 배포 (Vercel 서버리스 함수는 쓰지 않음) |
| 백엔드 | **Express (Node.js)** | REST API, 경찰청 API 프록시, LLM 호출, 주기적 수집 |
| 언어 | **JavaScript** | 프론트·백엔드 모두. 계산 규칙도 JS 순수 함수 |
| DB | **MySQL 8** (메모리 튜닝) | 분실물 검색 조건, 조회 코드, 수집한 습득물, 정리(정규화) 결과, 확인 이력 |
| 백엔드 배포 | **Docker** (docker-compose: backend + mysql) → **AWS EC2** | 담당: 이용민 |
| 외부 API | 경찰청 습득물정보 조회 서비스 (data.go.kr) | XML 응답, 기능별 일일 10만 건 |
| LLM | **Google Gemini API** (무료 티어) | 서버에서만 호출. 인터페이스로 분리해 두고, 실패하거나 한도를 넘으면 규칙 기반으로 대체 |

## 3. 세부 라이브러리 (기본안, 변경 가능)
| 용도 | 후보 | 이유 |
|---|---|---|
| XML → JSON | `fast-xml-parser` | 가볍고 의존성 없음 |
| MySQL 접근 | **`mysql2`** (promise API) + SQL 직접 작성 | 가벼움. 스키마는 `backend/src/db/*.sql`로 관리 |
| 주기적 수집 | `node-cron` | Express 프로세스 안에서 동작, 별도 워커 불필요 |
| 환경변수 | `dotenv` | API 키를 `.env`로 관리 (커밋 금지) |
| 조회 코드 생성 | `crypto.randomBytes` / `nanoid` | 추측하기 어려운 무작위 값 |
| 계산 규칙 테스트 | `Vitest` | Vite와 설정 공유, Jest 호환 문법 |
| API 테스트 | `supertest` | Express 엔드포인트 테스트 |
| 프론트 라우팅 | `react-router` | 입력 화면 / 결과 화면 / 조회 코드 화면 |

## 4. 디렉터리 구조(안)
```
OSS-TEAM04/          # 한 레포에 프론트 + 백엔드 (모노레포)
├─ front/             # React + Vite → Vercel (Root Directory: front)
│  └─ src/
├─ backend/           # Express → Docker → AWS EC2
│  ├─ src/
│  │  ├─ routes/      # /api/lost ...
│  │  ├─ services/    # policeApi, llm, collector(cron)
│  │  ├─ rules/       # 계산 규칙 (순수 함수: 코드 변환, 점수, 날짜, 지역, NEW 판정, 정렬)
│  │  └─ db/          # MySQL 연결, 스키마/마이그레이션
│  └─ test/
├─ docs/             # 기획 문서
├─ docker-compose.yml # caddy + backend + mysql
└─ .env.example
```
- 계산 규칙(`rules/`)은 DB나 HTTP에 의존하지 않는 **순수 함수**로 작성 → "화면 없이도 확인할 수 있는 계산 규칙" 조건 충족, 단위 테스트 대상

- Vercel 프로젝트 설정에서 **Root Directory를 `front`**로 지정

## 4-1. 브랜치 전략
- 기본(default) 브랜치: **`develop`** — 모든 작업 PR은 develop으로
- `main`: 배포·제출용. develop이 안정되면 develop → main으로 PR
- 작업 브랜치: `feat/#이슈번호-설명`, `fix/…`, `refactor/…`, `docs/…`, `chore/…`, `deploy/…`, `test/…`
- 자세한 규칙: 레포의 `CONTRIBUTING.md`

## 5. 수업 조건과 관련해 주의할 점
1. **메모리 512MB**: MySQL 8은 기본 설정으로 400MB 이상 사용할 수 있음. Node(약 100MB)와 합치면 초과할 위험이 있음 → `innodb_buffer_pool_size` 등을 줄이거나, DB를 512MB 계산에서 빼도 되는지 확인 필요
2. **유료 API 금지**: LLM이 유료라면 LLM 없이도 핵심 기능이 동작해야 함 → 수동 입력 폴백(드롭다운)과 규칙 기반 정규화가 **필수**
3. **조회 코드 방식**: 로그인 금지 조건과 맞음. 개인정보는 저장하지 않음
4. **기존 계획 변경**: 기획 문서의 "JSON 파일 저장" → **MySQL**로 변경

## 6. MySQL 메모리 튜닝(안)
`docker-compose.yml`의 mysql 서비스에 아래 설정 적용, 목표는 약 150~200MB
```ini
[mysqld]
innodb_buffer_pool_size = 64M
innodb_log_buffer_size  = 8M
max_connections         = 20
performance_schema      = OFF
table_open_cache        = 256
key_buffer_size         = 8M
tmp_table_size          = 16M
max_heap_table_size     = 16M
```
- Node 서버는 `--max-old-space-size=256` 정도로 제한
- 컨테이너에 `mem_limit`을 걸고 `docker stats`로 실측해 문서에 기록

## 7. 배포 구조
```
[브라우저] ──HTTPS──> [Vercel: React 정적 파일]
     │
     └──HTTPS /api──> [AWS EC2: Caddy 또는 nginx(HTTPS) → Express → MySQL]
                                         └─> 경찰청 API, Gemini API
```
### 프론트 (Vercel)
- Vite 빌드 결과물만 배포. 빌드 명령은 `npm run build`, 출력 폴더는 `dist`
- 직접 접속하거나 새로고침해도 SPA 라우팅이 되도록 `vercel.json`에 모든 경로를 `index.html`로 rewrite (예: `/lost/:code`)
- API 주소는 `VITE_API_URL` 환경변수로 지정. **이 값에는 키를 절대 넣지 않음** (빌드 결과에 그대로 노출됨)

### 백엔드 (AWS EC2)
- 프리티어 인스턴스는 RAM이 1GB → 6장의 MySQL 튜닝을 적용하고 swap 1~2GB 설정
- **HTTPS 필수**: Vercel 페이지는 HTTPS라서, 백엔드가 HTTP면 브라우저가 요청을 막음(mixed content) → **방법 A로 확정**
  - ✅ 방법 A (확정): 도메인을 연결하고 Caddy로 인증서 자동 발급 (예: `api.<도메인>` → EC2 탄력적 IP)
  - ~~방법 B~~ (채택 안 함): `vercel.json` rewrite로 `/api/*`를 EC2로 프록시 → 브라우저는 같은 출처로 인식해서 CORS도 불필요. 단 HTTP 대상 허용 여부와 응답 시간 제한을 사전에 확인해야 함
- CORS: Express `cors`에서 Vercel 도메인(배포 도메인 + 필요하면 프리뷰 도메인)만 허용
- 보안 그룹: 80/443만 열고 3306(MySQL)은 닫음. 키는 EC2의 `.env`에만 둠
- docker-compose 구성: `caddy`(443 → backend:3000) + `backend` + `mysql`. Caddy 인증서는 볼륨에 저장해서 재시작해도 유지
- EC2에는 탄력적 IP를 붙여 재시작해도 DNS가 깨지지 않게 함

## 8. Gemini 사용 메모
- 키는 서버 `.env`의 `GEMINI_API_KEY`에만 둠. 프론트에서는 호출하지 않음
- 응답은 JSON으로 강제(구조화된 출력 / responseSchema)하고, 서버에서 다시 유효성 검사
- 무료 티어는 분당·일일 호출 한도가 있음 → 습득물 정규화 결과는 `atcId` 기준으로 DB에 캐시하고, 수집 배치는 호출 속도를 조절
- 무료 티어에서는 입력 데이터가 모델 개선에 쓰일 수 있음 → 개인정보를 보내지 않음 (습득물 공개 데이터와 사용자 물품 설명만)
- 한도 초과나 오류가 나면 수동 입력과 규칙 기반 정규화로 대체 → "유료 API 없이도 동작" 조건 충족

## 9. 미정 사항
- 사용할 Gemini 모델 → **보류** (구현 단계에서 무료 한도를 확인해 결정. 모델명은 `GEMINI_MODEL` 환경변수로 두어 코드 수정 없이 바꿀 수 있게 함)
- 도메인: 어디서 살지 / 무료 도메인(DuckDNS 등)을 쓸지
