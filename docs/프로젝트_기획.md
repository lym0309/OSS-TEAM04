# [team04] 자연어 기반 분실물 매칭 서비스

> 상태: **아이디어 확정** (GitHub Issue #3, 교수님 승인 — 2026-11 첫째 주)
> 과목: 오픈소스프로그래밍 (3학년 2학기)

## 1. 한 줄 소개
분실물의 특징을 자연어로 입력하면 경찰청 습득물 데이터를 검색해 유사한 물건을 추천하고, 이후 새로 등록된 습득물도 확인할 수 있는 AI 기반 분실물 매칭 웹 앱.

## 2. 문제 정의
- **대상**: 지하철·버스·카페 등에서 물건을 잃어버린 뒤 LOST112를 며칠씩 반복 검색하는 수도권 통근·통학생
- **불편함**
  - 물품 종류·색상·지역·날짜 조건을 직접 설정해야 함
  - 같은 물건도 등록 명칭/분류가 달라 놓치기 쉬움 (예: 에어팟 프로 케이스 → '무선이어폰', '이어폰 케이스', '전자기기')
  - 분실 직후엔 미등록일 수 있어 며칠간 같은 검색 반복
  - 결과를 유사한 순서로 비교하기 어려움

## 3. ChatGPT와의 차별점
| 항목 | 내용 |
|---|---|
| 외부 데이터 | 경찰청 습득물 조회 API로 실제 등록 데이터 검색 |
| 데이터 축적 | 분실물 정보 + 마지막 확인 시점 저장 → 재방문 시 신규 후보 구분 |
| 결정적 결과 | 정해진 계산 규칙(JS 함수)으로 점수화 → 같은 입력엔 같은 결과 |
| 검색 단축 | LLM이 자연어 → 검색 조건 추출 |

## 4. MVP (가장 먼저 완성할 기능)
1. 자연어 입력 → LLM이 구조화된 검색 조건으로 변환
2. 사용자가 추출 조건 확인·수정 → 서버가 경찰청 API 호출
3. 물품 종류·색상·지역·날짜 유사도 계산 → 점수순 표시

**예시**
- 입력: "어제 저녁 2호선에서 검정 에어팟 프로 케이스를 잃어버렸어."
- 추출: 무선이어폰 케이스 / 검정색 / 서울 지하철 2호선 / 어제 저녁
- 결과: 매칭 점수순 목록, 일치 조건·습득일·보관장소·상세정보, 조회 링크 발급, 재접속 시 NEW 표시

## 5. 계산 규칙 (화면 코드와 분리된 JS 함수 + 단위 테스트)
1. **검색 조건 코드 변환**: 물품 종류·색상·지역 → 경찰청 API 분류 코드
2. **유사도 점수**: 종류 일치도 + 색상 유사도 + 지역 근접도 + 날짜 차이 가중합
3. **날짜 유효성**: 습득일 < 분실일이면 제외, 차이가 클수록 감점
4. **지역 근접도**: 동일 지역 고득점, 인접 지역 부분 점수 (예: 서울↔경기)
5. **신규 후보 판정**: 이전 조회 ID 목록과 비교해 NEW 표시
6. **정렬**: 점수 내림차순, 동점 시 습득일 등으로 결정
- (추가 검토) 보관 기한 안내 — 법적 기간·절차 확인된 경우만
- ※ 매칭 점수는 조건 유사성일 뿐, 소유권/동일 물품을 보장하지 않음

## 6. 서버 역할 (Express)
- 분실물 속성·조회 코드를 JSON 파일 등에 저장
- 경찰청 API 호출, XML → JSON 변환
- 경찰청 API 키·LLM API 키 서버에서 관리
- 동일 조건 반복 요청 캐시
- 이전 확인 ID vs 현재 결과 비교로 신규 후보 구분
- 로그인 없이 조회 코드로 접근 (추측 어려운 무작위 코드, 개인정보 미저장)

**엔드포인트 후보**
| Method | Path | 설명 |
|---|---|---|
| POST | `/api/lost` | 분실물 등록 + 조회 코드 발급 |
| GET | `/api/lost/:code/matches` | 저장 조건으로 검색, 유사도순 반환 |
| GET | `/api/lost/:code/new` | 이전 조회 이후 신규 후보 |
| PATCH | `/api/lost/:code` | 검색 조건 수정 |

## 7. LLM 사용처
- 사용자 설명 → 물품 종류, 색상, 브랜드, 분실 지역, 분실 일시, 특징을 JSON으로 추출
- 서버에서 유효성 검사 후 API 검색 조건으로 변환, 사용자가 확인·수정 가능
- LLM 실패 시 드롭다운/입력창 수동 선택으로 폴백
- (추가 검토) 습득물 제목·상세 설명에서 브랜드·특징 추출해 점수 반영

## 9. LLM(ChatGPT) 검토 지적 & 대응
1. **API 데이터 한계** (물품명·색상·브랜드 부족 시 유사도 부정확)
   → 초기엔 종류·날짜·지역·물품명 중심, 색상·브랜드는 제공 여부에 따라 추가. 유사도는 LLM 아닌 JS로 계산.
2. **조회 코드 한계** (분실·노출 위험)
   → 회원가입 없는 방식 유지. 무작위 코드, 개인정보 미수집, 링크 복사 보관 기능.

- → 경찰청 API가 습득물에 대해 실제로 어떤 정보를 주는지 빨리 확인하고, 사용자 입력과 같은 기준으로 정리하는 방법을 구체화할 것
- → **이 부분에도 LLM 활용 가능**

## 11. 경찰청 API 실측 결과 (2026-11-12 확인)
- 서비스: `https://apis.data.go.kr/1320000/LosfundInfoInqireService` (XML, 기능별 일일 10만 건)
- 개발계정 승인, 활용기간 2026-10-28 ~ 2028-10-28. 키는 `.env`로 관리 (커밋 금지)

| 기능 | 엔드포인트 | 상태 |
|---|---|---|
| 분류·지역·기간별 | `/getLosfundInfoAccToClAreaPd` | ✅ (11/1~11/11 기준 12,111건) |
| 명칭·보관장소별 | `/getLosfundInfoAccTpNmCstdyPlace` | ✅ (전체 598,377건) |
| 상세정보 | `/getLosfundDetailInfo` (`ATC_ID`, `FD_SN`) | ✅ |
| 위치기반 | `/getLosfundInfoAccToLc` (`ADDR`) | ⚠️ "시도 시군구" 형식 필요. "서울특별시"만 넣으면 HTTP_ERROR |

**목록 응답 필드**: `atcId`(관리번호), `fdSn`, `prdtClNm`(분류, 예 "휴대폰 > 삼성휴대폰"), `fdPrdtNm`(물품명), `clrNm`(색상), `fdSbjt`(제목), `fdFilePathImg`, `depPlace`(보관장소), `fdYmd`(습득일), `addr`(위치기반만)

**상세 응답 추가 필드**: `fdHor`(습득 시), `fdPlace`(습득 장소, 예 "택시"), `csteSteNm`(보관상태), `fndKeepOrgnSeNm`, `orgNm`/`orgId`/`tel`, `uniq`(특이사항 자유 텍스트)

**피드백 관련 시사점**
- 습득물 쪽에 이미 `prdtClNm`(대>소 분류), `clrNm`(정해진 색상 목록)이 있음 → 분류·색상은 코드 기준 비교 가능
- `fdPrdtNm`, `fdSbjt`, `uniq`는 자유 텍스트 → 브랜드·세부 특징은 여기서 LLM/키워드로 추출 필요
- **습득 장소(`fdPlace`)·시간은 상세 API에만 있음** → 후보마다 상세 호출 필요 (호출량·캐시 고려)
- 목록의 지역 정보는 `depPlace`(보관 기관)뿐 → 분실 장소 ≠ 보관 기관 문제
- 분류코드는 가이드 hwp 코드표로 확정 필요 (`PRH000`은 휴대폰이 아니라 지갑으로 나옴)

## 12. 결정 사항 (2026-11-12)
| 항목 | 결정 | 내용 |
|---|---|---|
| 습득물 정리(정규화) | **규칙 + LLM 혼합** | 분류(`prdtClNm`)·색상(`clrNm`)은 API 값을 공통 코드에 규칙으로 매핑. 자유 텍스트(`fdPrdtNm`·`fdSbjt`·`uniq`)는 LLM으로 브랜드·특징을 뽑아 `atcId` 기준으로 캐시. 사용자 입력도 **같은 스키마**로 추출 |
| 데이터 수집 | **주기적 수집 + 저장** | 서버가 정해진 주기로 최근 습득물을 수집해 정리한 뒤 JSON/DB에 저장. 검색은 저장본에서 수행. NEW는 `atcId` + 수집 시점으로 판정 |
| 지역 근접도 | **보관기관 + 상위 후보만 상세** | 1차 점수는 보관기관 지역으로 계산하고, 상위 N개만 상세 API로 습득 장소·시간을 받아 다시 점수화 |
| LLM 제공사 | **Gemini** | 무료 티어. 서버에서만 호출 |

**공통 스키마(안)** — 사용자 입력과 습득물 모두 이 형태로 변환
```json
{
  "category": { "main": "전자기기", "sub": "무선이어폰" },
  "color": "블랙",
  "brand": "Apple",
  "features": ["케이스", "프로"],
  "region": { "sido": "서울특별시", "sigungu": "마포구" },
  "place": "지하철 2호선",
  "date": "2026-11-11",
  "hour": 19
}
```
